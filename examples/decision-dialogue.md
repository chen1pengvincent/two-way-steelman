# 使用与人工验收示例

这是依据原提示词整理的输入与验收条件，不是一次真实 Agent 运行记录，也不保证模型逐字输出。

## 第一轮输入

「帮我用双向钢人论证分析：我想辞职做独立开发。我有六个月生活费，副业产品还没有付费用户，但现在的工作挤占了开发时间。我该不该直接辞职？」

## 第一轮预期

- 重述用户要解决的具体取舍：在收入保障与验证独立产品之间如何分配时间。
- 分别给出立即辞职和继续保留工作的最强论证，不把任何一方弱化为稻草人。
- 指出会改变结论的关键变量，例如实际付费需求、可承受的现金消耗和验证所需时间。
- 只提出一个最关键的问题，并等待回答；此轮不提前给最终判断。

可接受的问题示例：「在六个月储蓄用完前，你能用什么具体证据判断产品已出现可持续的付费需求？」这是示例，实际关键问题应由用户上下文决定。

## 第二轮输入

「我愿意先用八周做验证，目标是找到十位真实付费用户；如果达不到，我继续上班并缩小产品范围。」

## 第二轮预期

- 基于新信息给出明确判断、理由和下一步行动。
- 判断与行动回应上述现金和需求条件，例如先执行八周验证，再根据真实付费结果决定是否辞职。
- 不把对话示例当成所有职业决策的固定答案，也不把一个付费目标当成已经发生的事实。

## 安装后检查

在至少两个实际 Agent 中分别安装并运行以上两轮，保存 Agent 名称/版本、安装目录、完整输入输出和结果；最好再让其他使用者独立尝试。检查触发是否成功、双方论证是否充分、第一轮是否只问一个问题并等待，以及第二轮是否包含判断、理由和行动。纯事实查询不应触发本技能。

这些人工验收检查用于观察模型行为；打包单元测试和 YAML 解析不能替代它们。现有能力与已知局限仍以原 `SKILL.md` 和 README 为准。
