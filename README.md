# two-way-steelman · 双向钢人论证

> 来源于数字生命卡兹克

> 一个可安装到支持该标准的任意 Agent 的 Skill：逼 AI 先做一次「双向钢人论证」，把正反双方都强化到最强，只问你一个最关键的问题，等你回答后给出明确判断、理由和下一步行动。

## 这是什么

- **格式**：[Agent Skills 开放标准](https://agentskills.io/specification)（`SKILL.md` + YAML frontmatter），一个文件夹即可安装到支持该标准的任意 Agent。
- **技能名**：`two-way-steelman`
- **它做什么**：当你想把一个问题、想法或决策彻底想清楚时，它不会顺着你说，而是先：
  1. 用最完整、最有力的方式重述你真正想解决的问题；
  2. 分别给出支持与反对你当前想法的**最强**论证（钢人化双方，不歪曲任何一方）；
  3. 找出双方真正的分歧，以及最可能改变结论的关键变量；
  4. 只问你一个最关键的问题——**等你回答后**，才给出明确判断、理由和下一步行动。
- **它解决什么**：AI 最大的问题是谄媚。这个流程要求 AI 暂时放下你的立场，把你最容易忽略、最不愿面对的那一边也推到最强，再逼它给出不粘锅的明确结论。

## 安装

本仓库根目录就是技能目录（`SKILL.md` 位于仓库根，目录名与 `name` 字段一致）。

### 方式一：克隆到技能目录

支持 `~/.agents/skills/` 跨运行时别名目录的 Agent（Codex CLI、GitHub Copilot CLI、Gemini CLI 等）：

```bash
git clone https://github.com/chen1pengvincent/two-way-steelman.git ~/.agents/skills/two-way-steelman
```

Claude Code：

```bash
git clone https://github.com/chen1pengvincent/two-way-steelman.git ~/.claude/skills/two-way-steelman
```

其他 Agent：把本仓库文件夹复制到对应 Agent 的 skills 目录即可，**目录名保持 `two-way-steelman`**。

### 方式二：通过 skills.sh 生态安装

```bash
npx skills add chen1pengvincent/two-way-steelman
```

注：`npx skills add` 按仓库直接安装，无需事先登记；该技能要出现在 skills.sh 的搜索与榜单中，需随安装量累积遥测后才会浮现。

## 使用方法

装好后，直接把问题丢给它：

- 「帮我用双向钢人论证分析：我该不该辞职？」
- 「对这个想法做一次钢人论证 / steelman 一下」
- 或者只粘问题，说一句「帮我分析」

它会先问回你一个最关键的问题；你回答后，它才给出判断、理由与下一步行动。

## 设计理念（作者原话）

> 真正的钢人论证，它会逼着AI暂时放下你的立场，把你最容易忽略、最不愿意面对的那一边，让你直面面对。
> 因为所有人都知道，直到如今，AI最大的问题依然是谄媚，会不断的顺着你的观点说，即使强如Fable 5和GPT 5.6 Sol，依然如此。
> 所以，我觉得，钢人论证法这个内核，实在对我们大家来说，太有用了，因为真的能最大程度避免模型的谄媚。之所以叫双向钢人化，本质上不是为了让AI充当什么钢人跟你辩论，而是有一个我自己的小巧思在。
> AI = 执行钢人论证这个动作的人。
> 你的观点 = 第一个被钢人论证强化的对象。
> 反对你的观点 = 第二个被钢人论证强化的对象。
> 所以，最后AI手里会得到两个钢人强化后的最强版本。
> 这样，我觉得能最大程度的，帮我们找到这个问题最本质的答案。
> 整个Prompt一共做四件事。
> 第一件事，是重写你的问题。
> 因为这几年我其实发现一个现象，就是人这个物种啊，经常会把“自己嘴上问的”和“自己真正想解决的”混在一起。
> 就比如有人问要不要辞职，他其实真正担心的可能是再干三年，自己还会不会有竞争力等等，诸如此类。
> 所以当AI先把真实问题重述一遍，那样很多原本乱七八糟的东西，就已经清楚了大半了。
> 第二件事，是给强化正反双方。
> 就如同我上面所说，双向钢人论证会要求它把正反两边都推到最强。
> 那么我们就能知道，支持这件事的人，能拿出的最好证据是什么？
> 而反对这件事的人，最难回答的质疑又是什么？
> 当两边都不能靠歪曲对方取胜，真正的冲突才会开始显露出来。
> 第三件事，找出那个决定结论的变量。
> 很多复杂问题看起来有十几个因素，最后真正能改变答案的，可能只有一两个。
> 就比如我们工作的时候，预算是十万还是一百万，答案是一定会变的。
> 就比如你在公司经营中，究竟想要短期收入还是长期品牌，那答案就更不一样了。
> 所以，我希望这个Prompt在双向钢人论证之后，帮大家找到这个最核心的分歧和变量。
> 第四件事，逼AI给出明确判断和行动。
> AI经常在最终的结论上会不粘锅，给出一堆模棱两可没啥屁用的结论。
> 所以，最后，我要求它必须跟你提一个最关键的问题，然后，要求它必须给出判断、理由和下一步行动。

## 原文全文

```text
先别急着回答，也别默认我已经把问题想清楚。
请先对这个问题做一次详细思考的“双向钢人论证”：
1.用最完整、最有力的方式，重述我真正想解决的问题。
2.使用钢人论证法分别给出支持我当前想法、以及反对它的最强论证。
3.找出双方真正的分歧，以及最可能改变结论的关键变量。
4.只问我一个最关键的问题。
等我回答后，再给出明确判断、理由和下一步行动。
我的问题是：
[粘贴你的问题]
```

## 已知局限（红队审查发现）

以下问题经独立红队审查确认，根因在原始 prompt 本身（正文按作者要求逐字冻结，未做任何修改），列出供使用者知悉：

1. **结论的内容质量约束有限**：正文能强制「先问一个关键问题、等你回答后再给判断/理由/下一步行动」的结构，但强制不了判断的确定性——倾向谄媚的模型仍可能给出「取决于实际情况」式的和稀泥结论，效果上限取决于模型自身能力。
2. **用户未表态立场**：只问「我该不该 X」而没有说出自己倾向时，正文要求钢人化「我当前想法」，模型需自行把「做/不做」两侧各自钢人化（多数模型能正确兜底）。
3. **纯事实问题无降级出口**：正文是为决策流程设计的，对「XXX 是什么」类纯事实检索不适用，请勿用本技能做事实查询。
4. **多轮中途换题**：正文没有显式的「重新开始」子句，中途更换问题建议在消息里重新说明。
5. **description 中的中文**：个别 harness（如 Claude Code 技能选择器）展示中文 description 可能出现乱码，不影响安装与功能。
